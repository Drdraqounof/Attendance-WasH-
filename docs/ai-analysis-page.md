# Page Doc — AI Attendance Analysis (`/insights`)

**Date:** 2026-08-11
**Route:** `/insights`
**File:** `src/app/insights/page.tsx`
**Auth:** Server-guarded — redirects to `/login` if `hasDemoSession()` is false.
**Nav label:** "AI Insights" (see `src/components/ops-shell.tsx`)

## Purpose

Surfaces the plan's "AI attendance analysis" capabilities: frequent
lateness patterns, common causes, at-risk employees, improvement
trends, and reliability scores — plus a written executive summary at
the top of the page. It's the analysis counterpart to `/dashboard`
(live roster) and `/analytics` (aggregate charts).

## Page sections (top to bottom)

1. **Header + capability list** — title, subtitle, and a 2-column
   checklist of the five capabilities the page claims to cover
   (`CAPABILITIES` constant).
2. **AI summary** — a bordered card with a 3–5 sentence narrative.
   Labeled "Generated by OpenAI" or "Fallback" in the section's
   top-right corner depending on `narrative.source`, so it's always
   clear whether the text came from the model or the static fallback
   sentence. See [ai-integration.md](ai-integration.md) for how this
   call works.
3. **Frequent lateness patterns** — list of employees with 3+ late
   arrivals in the last 30 days, each with a quoted rule-based
   narrative sentence and a link to their profile.
4. **Common causes of attendance issues** (left column) — top 6
   incident-reason categories with a count and a proportional bar,
   from `signalTypeBreakdown()`.
5. **Employees at risk** (right column) — everyone above the "clear"
   risk band, sorted worst-first, with reliability score and reason,
   linking to their profile.
6. **Attendance reliability scores & improvement trends** — a table
   of every employee's reliability score (0–100) and 30-day trend
   (Improving / Stable / Worsening), highest score first.
7. **Footer disclosure** — "Demo data · rule-based stand-in for AI
   analysis · SMS intake not connected."

## Data flow

| Section | Source function | File |
| --- | --- | --- |
| AI summary | `generateInsightsNarrative()` | `src/lib/ai-narrative.ts` |
| Lateness patterns | `frequentLatenessPatterns(3, 30)` | `src/lib/ai-analysis-mock.ts` |
| Common causes | `signalTypeBreakdown()` | `src/lib/people-mock.ts` |
| At-risk employees | `employeesAtRisk(30)` | `src/lib/ai-analysis-mock.ts` |
| Reliability & trend | `reliabilityRanking(30)` | `src/lib/ai-analysis-mock.ts` |

All five section functions read from the same mock point ledgers
(`src/lib/people-mock.ts`), so the numbers across sections are always
internally consistent. The AI summary is the only section touching a
real external call (OpenAI) — everything else is deterministic
TypeScript math, which is why the footer explicitly calls the rest
"rule-based."

`InsightsPage` is an async server component: it awaits
`generateInsightsNarrative()` during render, so the whole page waits
on that one network call before responding. If OpenAI is slow or
down, `generateInsightsNarrative()` catches the error internally and
resolves to the fallback sentence rather than the page hanging or
erroring (see ai-integration.md).

## Visual/UX notes

- Staggered entrance animation across sections
  (`animate-fade-up-delay-1/2/3`) — matches the pattern used on
  `/dashboard` and `/analytics`.
- Causes/at-risk sit side-by-side on `lg:` and stack on smaller
  screens (`lg:grid-cols-2`).
- Reliability table scrolls horizontally on narrow viewports
  (`overflow-x-auto`) rather than compressing columns unreadably.
- Trend color coding: improving → `text-accent-deep` (teal),
  worsening → `text-danger-soft` (amber/red), stable → muted slate
  (`trendTone()`).
- Empty states are handled explicitly for both lateness and at-risk
  lists ("No employee has crossed…" / "No employees flagged…") rather
  than rendering an empty list.

## Known limitations (demo)

- No pagination — every list renders the full mock roster (11
  employees); fine at this scale, would need paging/virtualization
  before real data volume.
- AI summary calls OpenAI on every page load with no caching — see
  "Operational notes" in ai-integration.md for the cost implication.
- SMS intake (the plan's actual signal source) is not connected;
  everything here reads from static mock ledgers, not live messages.

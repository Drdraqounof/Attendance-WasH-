# Page Doc — AI Attendance Analysis (`/insights`)

**Date:** 2026-08-11 · **Updated same day:** streaming/caching/DB-backed rewrite
**Route:** `/insights?days=7|30|90`
**File:** `src/app/insights/page.tsx`
**Auth:** Server-guarded — redirects to `/login` if `hasDemoSession()` is false.
**Nav label:** "AI Insights" (see `src/components/ops-shell.tsx`)

## Purpose

Surfaces the plan's "AI attendance analysis" capabilities: frequent
lateness patterns, common causes, at-risk employees, improvement
trends, and reliability scores — plus a written executive summary at
the top of the page. It's the analysis counterpart to `/dashboard`
(live roster) and `/analytics` (aggregate charts).

## Page sections (top to bottom)

1. **Header + time window + capability list** — title, a `7d / 30d /
   90d` window switcher (links to `/insights?days=N`, active state
   highlighted), and a 2-column checklist of the five capabilities the
   page claims to cover (`CAPABILITIES` constant).
2. **AI summary** — a bordered card with a 3–5 sentence narrative,
   rendered by the isolated `AiSummaryCard` component inside a
   `<Suspense>` boundary (see "Streaming" below). Labeled "Generated by
   OpenAI" or "Fallback" in the section's top-right corner depending on
   `narrative.source`. See [ai-integration.md](ai-integration.md) for
   how this call works.
3. **Frequent lateness patterns** — employees with 3+ late arrivals in
   the selected window, each with a quoted rule-based narrative
   sentence and a link to their profile.
4. **Common causes of attendance issues** (left column) — top 6
   incident-reason categories with a count and a proportional bar,
   from `signalTypeBreakdown(days)`.
5. **Employees at risk** (right column) — everyone above the "clear"
   risk band, sorted worst-first, with reliability score and reason,
   linking to their profile.
6. **Attendance reliability scores & improvement trends** — a table of
   the top 10 employees by reliability score (0–100) with their trend
   (Improving / Stable / Worsening) vs. the prior window of equal
   length.
7. **Footer disclosure** — "Live query · reads from Neon (schema in
   docs/database.md) · SMS intake not connected."

## Data flow

| Section | Source function | File |
| --- | --- | --- |
| AI summary | `generateInsightsNarrative(days)` | `src/lib/ai-narrative.ts` |
| Lateness patterns | `frequentLatenessPatterns(days, 3)` | `src/lib/insights-queries.ts` |
| Common causes | `signalTypeBreakdown(days)` | `src/lib/insights-queries.ts` |
| At-risk employees | `employeesAtRisk(days)` | `src/lib/insights-queries.ts` |
| Reliability & trend | `reliabilityRanking(days, 10)` | `src/lib/insights-queries.ts` |

All five functions are backed by live Drizzle queries against the
Neon `employees` / `point_events` tables (see
[database.md](database.md)) — the mock files
(`ai-analysis-mock.ts`, `people-mock.ts`) are no longer read by this
page. `/analytics` still uses the mock files; they weren't touched.

`generateInsightsNarrative(days)` internally calls the same four
query functions to build its prompt, so the AI summary's numbers and
the sections below it are always consistent for a given `days` value.

### Streaming

`InsightsPage` awaits the four deterministic queries directly (they're
fast Neon HTTP reads), but does **not** await the AI summary. Instead:

```tsx
<Suspense fallback={<AiSummaryCardSkeleton />}>
  <AiSummaryCard days={days} />
</Suspense>
```

`AiSummaryCard` (`src/app/insights/ai-summary-card.tsx`) is its own
async server component that calls `generateInsightsNarrative(days)`.
React renders the skeleton first and streams in the real card once
that call resolves — so a slow or cold OpenAI call no longer blocks
the rest of the page. If OpenAI is slow or down,
`generateInsightsNarrative` catches the error internally and resolves
to the fallback sentence rather than the page hanging or erroring
(see ai-integration.md).

### Caching & time window

`generateInsightsNarrative` is wrapped in `unstable_cache`, keyed by
`days`, revalidated hourly — so switching between 7d/30d/90d each get
their own cache entry, and repeat loads of the same window skip the
OpenAI call entirely until it expires. See "2026-08-11 changes" in
[ai-integration.md](ai-integration.md) for verification details.

## Visual/UX notes

- Staggered entrance animation across sections
  (`animate-fade-up-delay-1/2/3`) — matches the pattern used on
  `/dashboard` and `/analytics`.
- Causes/at-risk sit side-by-side on `lg:` and stack on smaller
  screens (`lg:grid-cols-2`).
- Reliability table scrolls horizontally on narrow viewports
  (`overflow-x-auto`) rather than compressing columns unreadably.
- Trend color coding: improving → `text-accent-deep` (teal),
  worsening → `text-danger-soft` (amber/red), stable → muted slate
  (`trendTone()`).
- Empty states are handled explicitly for both lateness and at-risk
  lists ("No employee has crossed…" / "No employees flagged…") rather
  than rendering an empty list.

## Known limitations (demo)

- Lateness/causes/at-risk sections still render the full result set
  (11 employees at current seed size); only the reliability table is
  explicitly capped (`RELIABILITY_LIMIT = 10`). Fine at this scale —
  would need the same cap (or real pagination) on the other lists
  before real data volume.
- `days` only accepts 7/30/90 (`parseDays` falls back to 30 for
  anything else); no custom range picker.
- SMS intake (the plan's actual signal source) is not connected;
  `point_events` is currently populated by the seed script
  (`src/db/seed.ts`), not live messages.
